# V1.3 SEMANTIC CROSSWALK — ΚΑΘΕ ΝΕΑ ΕΝΝΟΙΑ → ΜΙΑ ΕΔΡΑ Ή ΡΗΤΟ ΚΕΝΟ

**Σκοπός (εντολή δημιουργού):** «κάθε νέα έννοια → μία υπάρχουσα έδρα ή ρητά νέο
κενό. Καμία δεύτερη παράλληλη αρχιτεκτονική.» Αυτό το αρχείο είναι ο έλεγχος
μη-διπλασιασμού του v1.3: αν μια έννοια δεν δένει σε υπάρχουσα έδρα, δηλώνεται
**`ΝΕΟ ΚΕΝΟ`** — δεν κρύβεται.

Στήλες: **έννοια v1.3** · **έδρα** (αρχείο/σύμβολο· «—» αν κενό) · **status**
(`REUSE` = υπάρχουσα έδρα, καταναλώνεται· `EXTEND` = υπάρχουσα έδρα, χρειάζεται
επέκταση· `NEW GAP` = δεν υπάρχει, δηλώνεται· `COMPOSE` = οι έδρες υπάρχουν, η
σύνθεσή τους είναι νέα).

## ΣΥΝΟΨΗ ΚΕΝΩΝ (τα `NEW GAP` που το v1.3 ΔΕΝ κρύβει)

1. **Coverage ledger / εθνική απογραφή** — το κεντρικό μηχανικό κενό του δημόσιου
   στόχου (AS-IS R-1). Κάθε `coverage-and-freshness` IssuedClaim εξαρτάται από αυτό.
2. **Level-7 jurisprudence plane** (ratio/obiter/holding/line-of-authority) —
   κατατεθειμένη σχεδίαση, status ✗· βάση του `jurisprudential-analysis` profile.
3. **Εκδοχοποιημένο OpenAPI + SDKs** — καμία API έδρα σήμερα (AS-IS EV-5).
4. **RBAC/MFA** στον ενεργούντα (cockpit intent + review) — καμία αυθεντικοποίηση.
5. **Η σύνθεση των typed `IssuedClaim` profiles** (χωρίς αριθμητικό στόχο) σε ένα
   εκτελέσιμο πρωτόκολλο — οι έδρες υπάρχουν, η ένωση είναι νέα.
6. **Root Authority ως συνεχής/ανακλητή κατάσταση** + **provider-adoption
   qualification** — νέες έννοιες κατάστασης/βαθμίδας.

**Καμία από αυτές δεν ανοίγει δεύτερη αρχιτεκτονική.** Κάθε `NEW GAP` είναι
capability/σύνθεση πάνω στο ίδιο υπόστρωμα (CPEI §4 αρχή: memory types ≠ stores·
εδώ: certificates ≠ νέα subsystems).
