# V1.3 SEMANTIC-CLOSURE CONSISTENCY AUDIT

**Σκοπός (εντολή δημιουργού):** «μηχανικός consistency audit που αποδεικνύει ότι οι
παραπάνω αντιφάσεις δεν υπάρχουν πλέον.» Ανά αντίφαση: **πριν** (η γνωστή
ασυνέπεια), **επίλυση**, **μηχανικός έλεγχος** (εντολή grep + αναμενόμενο). Design
only· καμία υλοποίηση, κανένα destruction pass.

**Εμβέλεια ελέγχων:** ο κατάλογος `CHANGE-PROPOSAL/`. Preamble:
`cd <repo-root>/deployment/collab/design/OMEGA2/CHANGE-PROPOSAL`.

## C1 — Issuer self-verdict (`verification_result` μέσα σε certificate)
**Πριν:** το κοινό envelope της v1 απαιτούσε `verification_result` σε κάθε cert — ο
εκδότης αυτο-ετυμηγορούσε «VERIFIED».
**Επίλυση:** τρία επίπεδα. `verification_result` ζει **μόνο** στο `VerificationReceipt`
(Layer C), που παράγει ο τοπικός verifier. Ρητή απαγόρευση στο IssuedClaim.
**Έλεγχος:**
```
grep -c 'ΚΑΝΕΝΑ .*verification_result. σε IssuedClaim' MACHINE-LEGAL-TRUST-PROTOCOL.md   # ≥1
# στο v1.3 το verification_result εμφανίζεται ΜΟΝΟ ως ρητή άρνηση (**ΠΟΤΕ**):
grep -c 'ΠΟΤΕ.*verification_result' CHANGE-PROPOSAL-v1.3.md                               # ≥1
grep -c 'verification_result' CHANGE-PROPOSAL-v1.3.md                                     # 1 (μόνο η άρνηση)
```

## C2 — «TrustBundle verified only with SHA-256» (αντιφάσκει PCL RS256)
**Πριν:** ο verifier «μόνο με SHA-256» — αδύνατο να ελέγξει RS256 υπογραφή/delegation.
**Επίλυση:** δύο πρωτόγονες: SHA-256 για inclusion, RS256/Ed25519 για signatures.
**Έλεγχος:**
```
grep -c 'RS256.*Ed25519\|Ed25519.*RS256' MACHINE-LEGAL-TRUST-PROTOCOL.md                  # ≥1
grep -ci 'verified only with sha-256\|μόνο με SHA-256. .*TrustBundle\|χωρίς εξάρτηση πέρα\nαπό SHA-256' *.md   # 0 ως απαίτηση
grep -c 'SHA-256 για inclusion.*RS256\|inclusion.*SHA-256.*signature' CHANGE-PROPOSAL-v1.3.md  # ≥1
```

## C3 — Ελεύθερο `claim` string ως input επαλήθευσης
**Πριν:** `claim` = ελεύθερο ανθρώπινο string, input του verifier.
**Επίλυση:** `claim_type` (κλειστό sum) + typed `payload`· ανθρώπινο κείμενο μόνο
`description`, ποτέ input.
**Έλεγχος:**
```
grep -c 'claim_type' MACHINE-LEGAL-TRUST-PROTOCOL.md                                       # ≥1
grep -c 'description.*ΠΟΤΕ input\|ΠΟΤΕ input επαλήθευσης' MACHINE-LEGAL-TRUST-PROTOCOL.md   # ≥1
```

## C4 — Canonical roots (pcl_text_root αντιφάσκει census-2)
**Πριν:** TEMPORAL-IDENTITY λέει `pcl_text_root` πεθαίνει· census-2 το κρατά — δύο ρίζες.
**Επίλυση:** μία authority root = `release_root`· `pcl_text_root` = legacy cross-check
(non-authoritative), versioned migration profile (era-1/era-2). Καμία optional 2η root.
**Έλεγχος:**
```
grep -c 'release_root' MACHINE-LEGAL-TRUST-PROTOCOL.md                                     # ≥1
grep -c 'pcl_text_root. = .*legacy\|pcl_text_root.*cross-check\|legacy cross-check' MACHINE-LEGAL-TRUST-PROTOCOL.md  # ≥1
```

## C6 — TrustBundle ως certificate & correction/revocation συγχωνευμένα
**Πριν:** TrustBundle «πιστοποιητικό»· CorrectionOrRevocationRecord ένωνε νομικό
αντικείμενο με key/delegation revocation· κοινά temporal fields παντού.
**Επίλυση:** TrustBundle = container (Layer B)· χωριστά
`legal-object-correction-or-withdrawal` και `trust-key-or-delegation-revocation`·
temporal μόνο όπου ισχύει (✔/✘ πίνακας §2).
**Έλεγχος:**
```
grep -c 'CONTAINER, ΟΧΙ certificate\|CONTAINER μεταφοράς' MACHINE-LEGAL-TRUST-PROTOCOL.md  # ≥1
grep -c 'legal-object-correction-or-withdrawal' MACHINE-LEGAL-TRUST-PROTOCOL.md            # ≥1
grep -c 'trust-key-or-delegation-revocation' MACHINE-LEGAL-TRUST-PROTOCOL.md               # ≥1
grep -c 'temporal: ✘' MACHINE-LEGAL-TRUST-PROTOCOL.md                                      # ≥1 (profiles χωρίς temporal)
```

## C9 — Revocation απόλυτη («pre-revocation stays valid»)

**Επίλυση:** `revocation_reason` + `revoked_at` + `invalid_from` + `compromise_known_at`·


## C10 — AS-IS αναπαραγωγιμότητα
**Πριν:** `...` σε paths, κομμένα digests, μία σελίδα CI, article-count ασαφές.
**Επίλυση:** πλήρεις εντολές (καμία `...`), 64-char digests, πλήρης CI pagination
(71 runs), article-count ρητά ως **artifact count**.
**Έλεγχος:**
